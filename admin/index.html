🛡️ Защита данных: Как это работает

  • Row Level Security (RLS): В Supabase для таблицы game_balance активирован RLS. Любой клиент с anon ключом может делать только SELECT. Любые UPDATE/INSERT/DELETE из игры или консоли блокируются базой данных.
  • Локальная изоляция: Админ-панель слушает только локальный интерфейс 127.0.0.1:5174.
  • Двухэтапное подтверждение (Staging): Изменения параметров сначала сохраняются в локальный черновик с визуализацией изменений. Отправка в Supabase происходит только после нажатия «Применить в Supabase» и подтверждения в модальном окне.
  • Live Supabase Realtime: Как только данные попадают в Supabase, запущенная игра мгновенно получает событие через WebSocket и обновляет баланс на лету.

SQL Скрипт миграции (schema.sql)

-- 1. Создание таблицы баланса с защитой RLS
CREATE TABLE IF NOT EXISTS game_balance (
  id TEXT PRIMARY KEY,
  category TEXT NOT NULL,
  key TEXT NOT NULL,
  name TEXT NOT NULL,
  data JSONB NOT NULL,
  version INT DEFAULT 1,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
ALTER TABLE game_balance ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow public read" ON game_balance FOR SELECT USING (true);
CREATE POLICY "Allow service_role write" ON game_balance FOR ALL TO service_role USING (true);
ALTER PUBLICATION supabase_realtime ADD TABLE game_balance;
